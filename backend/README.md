# CivicVoice Backend

CivicVoice is a development MVP for reporting and tracking civic issues. The frontend is the existing Next.js/React application at the project root. This folder contains the Flask API, MySQL schema, and VADER sentiment analysis.

> This is not a production service. The admin dashboard has no authentication, and the API should only be exposed locally.

---

## 1. What This Folder Contains

| File | Purpose |
|---|---|
| `app.py` | Flask app and the six API endpoints |
| `db.py` | MySQL connections, CRUD, reference generation, and statistics |
| `sentiment.py` | VADER wrapper with graceful failure handling |
| `schema.sql` | Tables and indexes for MySQL |
| `requirements.txt` | Python packages |
| `.env.example` | Template for local database and CORS settings |
| `tests/test_api.py` | `unittest` API suite |
| `start_mysql.ps1` | Starts the portable MySQL server |
| `stop_mysql.ps1` | Stops the portable MySQL server |

The frontend lives in `../app`, `../components`, and `../lib`. It is retained; it is not generated by this backend.

---

## 2. Prerequisites

- Python 3.10+ (this machine uses 3.13.3)
- Node.js and the existing npm dependencies for the Next.js frontend
- MySQL 8.x running on `127.0.0.1:3306`
- A MySQL database named `civicvoice`
- A separate test database named `civicvoice_test`
- A MySQL user named `civicvoice` with access to both databases

The local setup uses portable MySQL 8.4.9. Its data directory and configuration are outside this repository. Update `MYSQL_HOME`, `MYSQL_INI`, and `MYSQL_ROOT_PASSWORD` in `.env` if your paths differ.

## 3. Environment Variables

Copy the example file once:

```powershell
cd backend
Copy-Item .env.example .env
```

Then edit `.env`:

```text
FLASK_ENV=development
FLASK_PORT=5000

DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=civicvoice
DB_PASSWORD=your-local-password
DB_NAME=civicvoice
TEST_DB_NAME=civicvoice_test

CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

Only the `DB_*` and `CORS_ORIGINS` values are used by the Flask app. The `MYSQL_*` values are used only by the PowerShell helper scripts and must never be committed. `.env` is ignored by Git.

The frontend may also use `.env.local` at the project root:

```text
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:5000/api
```

If this is omitted, the frontend defaults to `http://127.0.0.1:5000/api`.

## 4. Database Setup

Start MySQL:

```powershell
.\backend\start_mysql.ps1
```

Create the databases and user once (use your own local password):

```sql
CREATE DATABASE IF NOT EXISTS civicvoice
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE DATABASE IF NOT EXISTS civicvoice_test
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER 'civicvoice'@'localhost' IDENTIFIED BY 'your-local-password';
CREATE USER 'civicvoice'@'127.0.0.1' IDENTIFIED BY 'your-local-password';
GRANT ALL PRIVILEGES ON civicvoice.* TO 'civicvoice'@'localhost';
GRANT ALL PRIVILEGES ON civicvoice_test.* TO 'civicvoice'@'localhost';
GRANT ALL PRIVILEGES ON civicvoice.* TO 'civicvoice'@'127.0.0.1';
GRANT ALL PRIVILEGES ON civicvoice_test.* TO 'civicvoice'@'127.0.0.1';
FLUSH PRIVILEGES;
```

Apply the schema to both databases. From the project root, using the portable MySQL client:

```powershell
$mysql = "C:\path\to\mysql-8.4.9-winx64\bin\mysql.exe"
$env:MYSQL_PWD = "your-local-password"
Get-Content -Raw .\backend\schema.sql | & $mysql -h 127.0.0.1 -u civicvoice civicvoice
Get-Content -Raw .\backend\schema.sql | & $mysql -h 127.0.0.1 -u civicvoice civicvoice_test
Remove-Item Env:MYSQL_PWD
```

Verify:

```powershell
$env:MYSQL_PWD = "your-local-password"
& $mysql -h 127.0.0.1 -u civicvoice -e "SHOW TABLES;" civicvoice
Remove-Item Env:MYSQL_PWD
```

The expected tables are `complaints`, `status_history`, and `complaint_counters`.

## 5. Install and Run the Backend

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python app.py
```

The API runs at `http://127.0.0.1:5000`.

Check it:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/api/health
```

Expected:

```json
{
  "status": "ok",
  "database": "ok"
}
```

If MySQL is stopped, the health endpoint returns `503` with `database: "unavailable"`.

---

## 6. Run the Frontend

From the project root:

```powershell
npm run dev
```

Open `http://localhost:3000`.

The frontend calls the Flask API with `fetch()`. Requests are cross-origin during development, so Flask must allow `http://localhost:3000` and `http://127.0.0.1:3000` through `CORS_ORIGINS`. Restart Flask after changing the origins.

If the React dependencies are missing:

```powershell
npm install
```

## 7. API Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/health` | Check Flask and MySQL |
| `GET` | `/api/complaints` | List, search, filter, and sort complaints |
| `POST` | `/api/complaints` | Create a complaint and analyze its description |
| `GET` | `/api/complaints/reference/<reference_number>` | Find one complaint by reference |
| `PATCH` | `/api/complaints/<complaint_id>/status` | Update status and append history |
| `GET` | `/api/statistics` | Dashboard totals and distributions |

Detailed request and response examples are in [`../specs/api-spec.md`](../specs/api-spec.md).

## 8. Reference Numbers

References use the format `CV-YYYY-NNNNN`, for example `CV-2026-00001`.

Generation is database-backed:

1. The current UTC year is selected.
2. The matching `complaint_counters` row is locked with `SELECT ... FOR UPDATE`.
3. `last_number` is incremented.
4. The complaint and its initial `Submitted` history row are inserted in the same transaction.
5. A unique constraint on `reference_number` is the final duplicate safeguard.

The counter is per year, so a new year starts again at `00001`. References survive Flask restarts.

---

## 9. Sentiment

VADER analyzes the complaint **description** when it is created. The stored label is `positive`, `neutral`, `negative`, or `NULL`, and the score is the VADER compound score from `-1.0` to `1.0`.

- `compound >= 0.05` → positive
- `compound <= -0.05` → negative
- otherwise → neutral

If VADER fails, the complaint is still saved with `NULL` sentiment values; the failure is logged. Sentiment describes the **wording/tone** of the report, not its severity or whether it is true. It is not recalculated when the status changes.

## 10. Tests

The tests use Python's built-in `unittest` and the Flask test client. They run against `civicvoice_test`, never the development database. The suite refuses to run if `DB_NAME` does not end in `_test`.

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
$env:DB_NAME = "civicvoice_test"
python -m unittest discover -s tests -v
```

The suite clears only the test database tables before each test.

---

## 11. Stopping MySQL

```powershell
.\backend\stop_mysql.ps1
```

MySQL is not installed as a Windows service. Start it again with `start_mysql.ps1` after a reboot.

---

## 12. Limitations

- No authentication or roles; anyone who can reach the admin page can update statuses.
- No image or file uploads.
- No email, SMS, maps, pagination, or production deployment setup.
- Sentiment is a rough tone indicator.
- The API is intended for local development only.
- Existing browser `localStorage` demo data is not migrated to MySQL. The database starts empty unless demo rows are added manually.
